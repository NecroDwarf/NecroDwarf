# Добавление контента проектов

Данные редактируются в `src/app/projects/{id}/meta.ts`. Общие типы находятся в
`shared/content/types.ts`. Каждый `meta` проверяется типом `ProjectMeta`.
Короткое описание `description` используется также в карточках и SEO.
Обязательные поля: `id`, `name`, `category`, `description`, `tagline`, `theme`.
Текущие тексты и три проекта сохранены без содержательных изменений.

## Необязательные поля

- `status`: `idea`, `development`, `beta`, `released`, `paused`. В интерфейсе:
  «Идея», «В разработке», «Бета», «Выпущен», «Приостановлен».
  Заполнять только после подтверждения командой; отсутствие не означает конкретный статус.
- `longDescription`: массив абзацев подробного описания. Для длинных материалов
  дальнейшего этапа предусмотрен MDX; новая зависимость сейчас не добавлена.
- `features`: массив подтверждённых ключевых особенностей.
- `platforms`: массив названий доступных платформ.
- `links`: объект с необязательными ключами `github`, `website`, `documentation`,
  `download`. Используйте рабочие HTTPS-адреса или существующие внутренние маршруты.
  Не добавляйте ссылку до готовности страницы или файла.
- `cover`: изображение для карточки и вступления; имеет приоритет над `Art`.
- `gallery`: массив изображений. Пустой массив и отсутствие поля скрывают галерею.
- `Art`: существующий компонент декоративной SVG-иллюстрации. Необязателен,
  если у проекта нет иллюстрации или используется `cover`.

`ProjectIntro` автоматически показывает заполненные поля. Пустые списки не создают
секций, отсутствующие ссылки не создают кнопок. Ни одному из текущих проектов
не присвоены новые статусы, платформы или возможности.

## Изображения

Храните изображения в папке своего проекта, например
`projects/maniac/assets/gallery/`, и импортируйте их из `meta.ts` средствами Vite.
Каждое изображение имеет тип `ProjectImage`:

```ts
import screenshot from "./assets/gallery/descriptive-name.webp";

// Форма записи для будущего подтверждённого изображения, не публичная заглушка:
const image = {
  src: screenshot,
  alt: "Описание того, что действительно изображено на снимке",
  width: 1200,
  height: 800,
  caption: "Необязательная подпись",
};
```

Указывайте реальные исходные размеры. Для содержательных изображений нужен
информативный `alt`; для чисто декоративных допустим `alt: ""`.
Карточки используют общую область обложки и `object-fit: cover`: края могут
обрезаться. Размещайте существенные детали ближе к центру. Во вступлении и галерее
сохраняются исходные пропорции без обрезания. Галерея адаптивная, все изображения
в ней используют `loading="lazy"` и `decoding="async"`; обложка вступления не lazy.
Для веба предпочитайте WebP/AVIF при заметном выигрыше размера. Важные исходники
при необходимости храните отдельно в папке проекта и не импортируйте в сборку.
Не используйте вымышленные скриншоты или чрезмерно большие файлы.

## Обновления и дополнительные секции

Релизы хранятся в `projects/{id}/changelogs/registry.ts`. Пример действующей
структуры — Maniac. При появлении подтверждённых выпусков подключите их массив
в запись проекта в `projects/registry.ts` вместо `[]`. Общая лента формируется
автоматически из `publishedReleases`; не копируйте туда метаданные.
`draft` исключаются из опубликованной ленты. Неизвестную дату не придумывать.

Страница проекта управляет своим составом секций в `projects/{id}/pages/`.
Не выводите секцию истории и ссылку на неё, когда опубликованных релизов нет
(пример условного вывода — `ManiacPage`). `ReleaseList` без записей возвращает `null`.
Собственные секции, MDX и темы также размещайте внутри папки проекта.
`ProjectGallery` можно отдельно использовать в такой секции.

## Новый проект — после отдельного решения команды

1. Создайте `projects/{id}/meta.ts`, `pages/`, `assets/`, `theme/` по существующим образцам.
2. Типизируйте `meta` как `ProjectMeta`; задайте уникальный URL-безопасный `id`.
3. Страница использует `ProjectIntro`, дополнительные секции и собственные стили.
4. Добавьте импорт метаданных, страницы и запись `{ ...meta, Page, releases: [] }`
   в `projects/registry.ts` (или подключите реальные релизы).
5. Каталог, главная, базовый маршрут и SEO возьмут данные из реестра автоматически.
   Публикуйте запись только когда сама страница готова.
6. Выполните `npm run typecheck`, `npm run build`, `npm run check`,
   `npm run format:check`, затем проверьте браузер на 320, 390, 768, 1440 px.

Сейчас публичный список остаётся прежним: Maniac, FriendSheep, NovellMaker.
Подготовительный этап не открывал новые маршруты, Wiki и полные хроники.
На этапе 2A страница Maniac получила собственные данные в `projects/maniac/content.ts`,
секции Horror Tech. Загрузка Flower Cleaning 1.2 теперь ведёт прямо на проверенный
Google Drive download; резервное зеркало — публичная ссылка Яндекс Диска. Адреса
и версия сборки заданы один раз в `content.ts`, отдельно от будущих выпусков.
Архив содержит `mods.zip` и `world.zip`; инструкция соответствует этой структуре.
При обновлении ссылки проверяйте ZIP-сигнатуру и содержимое, а также контрольные
суммы зеркал. Архивы храните вне репозитория сайта, временные подписанные URL
не сохраняйте в коде. Источники
и ограничения — в `projects/maniac/CONTENT_SOURCES.md`. Новых маршрутов нет.

## Полные хроники Maniac — этап 2B

Релиз получает необязательный `href` на внутреннюю опубликованную страницу;
`source` сохраняет оригинальный внешний источник. ReleaseList использует href,
а при его отсутствии — source. Общая лента `/changelog` остаётся общей.
Страницы Maniac находятся в `projects/maniac/changelogs/`, полный текст — в
`content/`, снимки игровых данных — в `wiki/data/`. Не подставляйте современные
характеристики в release-снимки и не создавайте Wiki-ссылки до публикации статей.
Инструкции проверки полноты: [MANIAC_2B_VERIFICATION](docs/MANIAC_2B_VERIFICATION.md).

## Персонажи Maniac Wiki — этап 3A

Единый реестр персонажей — `wiki/data/characters.ts`. Облегчённый
`character-catalog.json` и отдельные `character-articles/*.json` получаются из
закреплённых Java-классов и русской локализации. Не изменяйте сгенерированные
описания вручную: обновляйте закреплённый источник и повторяйте подготовку.
Исторические `release:*` сохраняются отдельно от проверенных `source:*`.

Статьи подключены через `routePage` и отдельные entry-модули. Только Keeper entry
подключает viewer; движок и GLB — по кнопке. `publishedEntityRoutes` содержит
только действительно опубликованные статьи. У остальных категорий нет фиктивных URL.
Инструкция подготовки, список источников и тесты: [MANIAC_3A_VERIFICATION](docs/MANIAC_3A_VERIFICATION.md).

## Перки и способности Maniac Wiki — этап 3B

`scripts/prepare-maniac-perks.py` сверяет регистрацию, Builder, локализацию и
исполняющие классы закреплённого commit. Запускать из `website` с Python/Pillow;
`--fetch` разрешает получение недостающих файлов в игнорируемый `.audit` корня.
Каждый файл проверяется по Git blob SHA дерева; runtime-запросов к GitHub нет.
Неподдержанные выражения останавливают подготовку вместо подстановки догадок.

Облегчённые `perk-catalog.json` / `ability-catalog.json` подключены к единому
реестру. Полные описания — в отдельных `perk-articles` / `ability-articles`,
entry-модули — в `wiki/pages/perks` / `abilities`. Не импортируйте все статьи
из общего index. Маршруты используют существующий `routePage`; SSG и клиент
предзагружают выбранный entry перед рендерингом/гидратацией.

Сохраняйте стабильные ID, отдельно `source:*` и `release:*`. Не пересоздавайте
`maniac-3b-historical-sha256.json` ради прохождения проверки: он фиксирует
21 существовавшую историческую revision. Исторические 15 Flower-иконок тоже
не заменяются. Новые PNG преобразуются в lossless WebP с прозрачностью,
provenance хранит исходные и выходные хеши и размеры.

После подготовки выполните Prettier для обновлённых TS/JSON, все npm-проверки
и браузерный аудит. Ручные поправки подтверждённых расхождений вносите в
скрипт подготовки с объяснением и источником, а не в его выходные JSON.
Публикуйте сущность в `publishedEntityRoutes` только вместе с готовой статьёй.
Сейчас опубликованы 71 сущность: 15 персонажей, 44 перка, 12 способностей.
Полные предметы, механики и карты остаются следующим этапом.

Подробности, ограничения и команды: [MANIAC_3B_VERIFICATION](docs/MANIAC_3B_VERIFICATION.md).
