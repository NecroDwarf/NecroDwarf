# NecroDwarf — ТЗ на три дизайн-прототипа

**Этап:** визуальное исследование / выбор направления дизайна  
**Статус:** демонстрационные версии, не финальный сайт  
**Рабочая папка:** `website/`  
**Обязательные правила:** `website/AGENTS.md`  
**Язык сайта:** русский

## 1. Цель

Создать **одно локально запускаемое демо-приложение на React + TypeScript + Vite** с тремя **визуально самостоятельными** концепциями обновлённого сайта NecroDwarf. После просмотра команда выберет стилистическое направление для последующей полноценной разработки.

NecroDwarf — независимая команда разработчиков **разноплановых проектов**: игр, модов, веб-сервисов, приложений, ботов. Сайт должен представлять команду в целом, а не выглядеть как сайт исключительно Minecraft-мода или игровой студии.

**Главный критерий успеха:** три концепции должны ощущаться как три разных дизайн-предложения, а не один макет, перекрашенный в разные цвета.

## 2. Где работать и что не менять

- Новый код создавать только в `website/` внутри существующего репозитория.
- Не менять `src/` Minecraft-мода, Gradle, корневой `AGENTS.md` и старый сайт в `docs/`.
- Существующие файлы `docs/index.html`, `docs/js/main.js`, `docs/css/` и `docs/changelogs/maniac/` читать как **источник фактического контента и узнаваемых элементов**, не копировать старую HTML/JS-архитектуру.
- Учитывать `website/AGENTS.md`. Если `website/` уже содержит файлы, сначала изучить их и сохранить пользовательские изменения.
- Не выполнять полноценную миграцию текущего сайта на этом этапе.

## 3. Что именно разработать

Одно React-приложение с четырьмя адресами:

| Путь | Назначение |
| --- | --- |
| `/` | Небольшая страница выбора концепции, с названиями и ссылками на все три демо. |
| `/neo-tech` | Концепция 01: Neo Tech. |
| `/dark-forge` | Концепция 02: Dark Forge. |
| `/neo-forge` | Концепция 03: Neo Forge (гибрид). |

Каждое демо — **одна полноценная прокручиваемая landing page**, а не только первый экран и не набор абстрактных UI-карточек. В верхней части каждой страницы разместить **ненавязчивый способ переключиться на другие концепции** (можно компактную fixed-панель «Концепт 1/3»). Он должен быть легко доступен, но не доминировать над дизайном.

**Разрешённое поведение:** открытие трёх демо, переход на страницу выбора, якорная навигация по секциям, простые hover/focus и декоративные анимации. **Не нужны:** бизнес-логика, backend, CMS, авторизация, API, магазин, фильтры, формы или реальные страницы отдельных проектов.

Не рисовать неработающие элементы так, словно они кликабельны. Если ссылка нужна для демонстрации, пусть ведёт на реальный уже доступный адрес или к существующей секции; остальное оформлять как статический элемент.

## 4. Общий контент для честного сравнения

Во всех трёх концепциях использовать **одинаковые реальные названия, одинаковые смысловые блоки и примерно одинаковый объём текста**. Содержимое вынести в общие данные, независимые от стилей. Различаться должны **композиция, визуальный язык, типографика, ритм, сетка, оформление компонентов и анимации**.

Обязательные блоки (одинаковый набор, композиция внутри может меняться):

### 4.1. Шапка / навигация
- Название или знак `NecroDwarf`.
- Основные пункты: `Главная`, `Проекты`, `Хроники`, `О команде`.
- Пункты могут вести на якоря внутри демо.

### 4.2. Первый экран (hero)
- Выразительная фирменная типографика и композиция.
- Суть: **«NecroDwarf — независимая команда разработчиков»**.
- Короткая фраза из текущего позиционирования: разрабатываем игры, приложения, сервисы и инструменты ради интереса, опыта и любви к созданию.
- Один явно узнаваемый визуальный мотив бренда (символ, рунный знак, огранённый нефрит, кузнечная геометрия, абстрактная энергия), соответствующий концепции.
- Можно показать статичный призыв «Наши проекты», если он якорно прокручивает к каталогу.

### 4.3. Избранные проекты
Для прототипов достаточно четырёх карточек с данными, взятыми из текущего сайта:

1. **FriendSheep** — сервис организации мероприятий; веб, мобильное приложение, Telegram-бот.
2. **Maniac** — игровая адаптация асимметричного противостояния в Minecraft, собственные карты, классы и механики.
3. **Kingdoms of Chat** — социально-экономическая RPG для Telegram.
4. **Die Dice Paradise** — тактический рогалик, построенный вокруг бросков кубиков.

Использовать краткие описания на базе `docs/index.html` / `docs/js/main.js`. Статусы, если показываются, брать только **как они записаны в текущем сайте**, не выдавая их за независимо подтверждённые на сегодня. Не придумывать даты, загрузки, пользовательские метрики, отзывы, скриншоты продукта или возможности.

**Не включать в витрину этих прототипов** The Ancient Guardians и Dota: Legend of Creeps: в текущем сайте это Legacy/замороженные направления. Не удалять их материалы из исходного проекта. Вопрос окончательного списка проектов решается отдельно, после выбора дизайна.

### 4.4. Хроники / обновления
- Небольшая визуальная секция последних обновлений Maniac.
- Использовать подтверждённые названия: **Maniac Reforge 1.0**, **Кошмарный додеп 1.1**, **Flower Cleaning 1.2**.
- Для 1.2 допускается короткое содержательное описание (15 новых перков, цветочная тематика и исправления матчей) из существующего changelog.
- **Не переносить** полные страницы обновлений, таблицы перков и все патчноуты сейчас.

### 4.5. О команде
- Короткая презентация команды как независимых энтузиастов и разработчиков разного программного обеспечения.
- Можно визуально обыграть стек из текущего сайта (React, Node.js, Go, PostgreSQL, Minecraft modding и др.), без попытки придумывать участников или достижения.

### 4.6. Футер
- Название NecroDwarf и краткая подпись.
- Несколько уместных декоративных деталей в стилистике выбранного варианта.

## 5. ДНК бренда и палитра

Название объединяет две ассоциации:

- **Necro** — некромантия, нефритовая магическая энергия, таинственность.
- **Dwarf** — камень, металл, кузница, бронза, руны, ремесленная точность.

**Нефритовый — обязательный центральный фирменный цвет во всех трёх концепциях.** Бронза подчёркивает дварфийскую часть бренда, но не должна полностью вытеснять нефрит.

| Роль | Имя | HEX |
| --- | --- | --- |
| Главный фирменный | Jade | `#00A86B` |
| Темнее | Deep Jade | `#176B50` |
| Энергия / свечение | Jade Glow | `#53CFA1` |
| Почти чёрный | Void | `#090E0C` |
| Тёмный камень | Stone | `#17211C` |
| Металлическая поверхность / бордер | Iron | `#293830` |
| Состаренная бронза | Forge Bronze | `#B69A62` |
| Светлый текст | Bone | `#E7E2D4` |
| Приглушённый текст | Ash | `#9CAEA2` |

Допустимы производные оттенки и градиенты, если они поддерживают выбранное направление. Избегать кислотно-лаймового зелёного и чрезмерно яркого свечения. Текст должен оставаться хорошо читаемым.

## 6. Три разных направления

### 6.1. Концепция 01 — **Neo Tech**

**Впечатление:** современная технологичная команда, инженерная точность, digital-портфолио.

- Строгая модульная / асимметричная сетка; крупная современная sans-serif типографика, чёткие линии.
- Графитовые поверхности, местами прозрачность и blur, аккуратные интерфейсные метки и индексы.
- Jade — технологический акцент в геометрии, карточках и навигации.
- Дварфийское выражение через «точность инженерной конструкции» и геометрию, а не буквальные средневековые украшения.
- Возможны стильные микроанимации и тонкий фон-grid, но без типового «крипто / Web3 SaaS» шаблона.
- Композиция карточек, hero и хроник должна выглядеть современно и не повторять вариант Dark Forge.

### 6.2. Концепция 02 — **Dark Forge**

**Впечатление:** древняя дварфийская кузница, некромантическая гильдия, премиальное тёмное фэнтези.

- Тёмный камень, матовый металл, состаренная бронза, нефритовая мистическая энергия.
- Деликатные руны, гравировки, рельефные рамки, атмосферные фоны, тонкие орнаменты.
- Выразительная декоративная типографика **только для заголовков**; текст, карточки и навигация должны читаться легко.
- Более кинематографичная композиция hero; карточки проектов — как отдельные артефакты/таблички, но с нормальной UX-иерархией.
- Можно использовать простые CSS/SVG-символы без необходимости генерировать тяжёлые иллюстрации.
- Не делать сайт похожим на игровой форум 2010-х или MMORPG-инвентарь; команда занимается и сервисами, и приложениями.

### 6.3. Концепция 03 — **Neo Forge** (гибрид)

**Впечатление:** современная студия разработчиков с характерной нефритово-дварфийской идентичностью.

- Современная редакционная / студийная композиция, сильная типографика, чистая сетка и крупные блоки.
- Фэнтези-мотивы **точечные**: фирменный знак, небольшой орнамент, рунический разделитель, гравировка, бронзовая кромка, стилизованный нефритовый кристалл.
- Jade играет первую роль, бронза аккуратно усиливает образ кузницы.
- Баланс между выразительностью и универсальностью: органично показывает и Maniac, и FriendSheep.
- **Важно:** это не Neo Tech с фэнтези-картинкой. Нужны собственная визуальная композиция, динамика, оформление карточек и характер шрифтов.

## 7. Требования к реализации

- Стек: **React + TypeScript + Vite**. React Router допустим для маршрутов (или иной простой корректный способ); тяжёлые дополнительные зависимости не нужны.
- Три концепции хранить в **разных папках** с изолированными стилями. Общие контентные данные — отдельно; общие утилиты — по необходимости. Не собирать один компонент с огромным `if (theme === ...)` и общим макетом.
- Пример ожидаемой организации (ориентир, не требование дословно):

```text
website/
  AGENTS.md
  DESIGN_PROTOTYPES_TZ.md
  package.json
  index.html
  src/
    app/
    data/
      projects.ts
      changelogs.ts
    components/
      ConceptSwitcher.tsx
    concepts/
      neo-tech/
        NeoTechPage.tsx
        NeoTechPage.module.css
      dark-forge/
        DarkForgePage.tsx
        DarkForgePage.module.css
      neo-forge/
        NeoForgePage.tsx
        NeoForgePage.module.css
    styles/
      globals.css
    main.tsx
```

- Стили без конфликтов; CSS Modules подходят. Не требуется вводить Tailwind, UI-kit, сложную систему design tokens или тяжёлую анимационную библиотеку только ради демо.
- Адаптивная компоновка для desktop (~1440 px) и mobile (~390 px), без горизонтального скролла. Удобная мобильная навигация (возможно упрощённая).
- Корректная семантика, контраст, видимый focus, поддержка `prefers-reduced-motion`.
- Анимации минимальные и функциональные: hover, появление, тонкое свечение; без перегруза и постоянной тяжёлой нагрузки на браузер.
- Не рассчитывать на нестабильные внешние картинки и случайные фотостоки; использовать доступные и уместные материалы сайта, CSS/SVG-графику, текстовый бренд-знак и простые локальные элементы. Если оригинального лого нет в исходниках, не делать вид, что он существует.
- Не выдумывать «реальные» отзывы, командные фотографии, статистику, ссылки или достижения.

## 8. Чего сейчас НЕ делать

- Не переписывать весь существующий сайт, не переносить все changelog и все страницы проектов.
- Не разрабатывать backend, API, базу, админку, аутентификацию, интеграции, загрузки, SEO-стратегию или деплой.
- Не настраивать домен/хостинг и не менять текущий GitHub Pages.
- Не удалять архивные материалы или проектные файлы.
- Не тратить время на оптимизацию несуществующей сложной архитектуры. Цель — **визуально убедительные концепты**, а не production-ready портал.

## 9. Критерии приёмки

1. Из одной команды запускается одно приложение (`npm install`, `npm run dev`).
2. Работают `/`, `/neo-tech`, `/dark-forge`, `/neo-forge`; понятное переключение между ними.
3. Во всех трёх демо есть навигация, hero, проекты, хроники, о команде, футер.
4. Во всех демо **единый фактический контент**, но **заметно разная** сетка, композиция, типографика, карточки и детали.
5. Нефритовый `#00A86B` — узнаваемая часть всех дизайнов; дварфийская составляющая есть, но разная по интенсивности.
6. Каждый концепт смотрится как законченная мини-страница, а не wireframe.
7. Страницы удобочитаемы на 1440 px и 390 px, нет горизонтального скролла.
8. Нет бессмысленных кнопок и обещаний несуществующей функциональности.
9. `npm run build` проходит (или дана конкретная причина невозможности проверки).
10. Не изменены Minecraft-мод, старый сайт в `docs/`, корневой `AGENTS.md` и несвязанные файлы.

## 10. Как отчитаться по завершении

Кратко сообщить:

- где лежат файлы и как запустить (`cd website`, `npm install`, `npm run dev`);
- какими маршрутами открыть три концепции;
- главное визуальное отличие каждого концепта (по 2–3 предложения);
- какие файлы созданы/изменены;
- что проверено (`npm run build`, проверка маршрутов и т. п.), а что не удалось проверить;
- какие решения по стилю можно обсудить с командой дальше.

**Не начинать второй этап** — полную миграцию, разработку продакшен-архитектуры или деплой — без отдельного задания.
