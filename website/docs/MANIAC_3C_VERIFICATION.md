## Предметы, получение и визуальные источники

В каталоге работают поиск, категории и фильтр по подтверждённой связи с
персонажем. Без JS виден весь список. Статья отделяет назначение, доступность,
применение, параметры, связи и сворачиваемые источники. Неизвестные числа
не превращены в нули. Ранее проверенные характеристики предметов сохранены.

`CharacterLoadoutPreview` и справочник класса используются как свидетельство
назначения и связи. Они не объявлены доказательством универсальной стартовой
выдачи. GameManager подтверждает отдельную раздачу Игл пробуждения: при активном
Хранителе случайным активным выжившим выдаётся ceil(N / 3) игл. Предметы перков
имеют отдельную логику создания и привязки владельца.

Подготовлены 49 новых изображений предметов: 33 плоских lossless WebP и
16 статичных PNG-рендеров оригинальных Minecraft JSON-моделей, включая компьютер.
Открытая Кошмарная зажигалка переиспользована без изменения её PNG/модели.
Для прежней ванильной экипировки сохранены уже проверенные локальные спрайты.

Build-time renderer учитывает цепочку parent, texture references, elements,
UV/rotation граней, вращение элементов с pivot/rescale и GUI display transform.
Используется ортографическая камера с нормализацией кадра, прозрачный фон,
nearest-фильтрация оригинальных текстур. Это иллюстрации оригинальной геометрии,
не обещание идентичного освещения Minecraft. Three.js не добавлен в runtime статей.

Есть честные исключения, отражённые в каждой статье и аудите:

| Ресурс                                     | Ограничение                                                                                            | Представление                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| Коса Смерти                                | В JSON есть неразрешённая грань `#missing`                                                             | Текстовая карточка; ошибочный частичный рендер не опубликован              |
| Планшет Агента, Чумная лампа, Розовые очки | builtin/custom renderer или сложная модель без подтверждённого автоматического экспорта                | Текстовая карточка; атлас не выдаётся за предмет                           |
| Clarity                                    | Нет модели по точному lowercase registry path; в дереве присутствует `Clarity.json` с другим регистром | Текстовое представление с фиксацией отсутствующего точного пути            |
| soul_essence                               | Надёжная иконка не установлена                                                                         | Текстовая карточка материала ремонта                                       |
| Пистолет Агента                            | Описание класса говорит о пистолете, а превью использует IRON_SWORD                                    | Старый ID сохранён; модель пистолета и гарантированная выдача не придуманы |

Для generator и soul_essence нет соответствующего русского ключа названия:
использованы описательные заголовки «Генератор Фредди» и «Материал ремонта брони»,
registry ID остаётся доступен в источниках. Они не объявлены дословными локализованными именами игры.

Пути, размеры, SHA-256 и преобразования — в
`assets/wiki/systems/imports.json`, `guide-imports.json` и общем `assets/imports.json`.
Исходные Java/JSON/PNG проверены по Git blob SHA pinned-дерева; их SHA-256
хранятся в `wiki/data/provenance.json`. Нет runtime-запросов ассетов к GitHub.

## Механики и спорные сведения

28 статей объясняют правила и действия игрока: подготовку, фазы, таймер,
цели/завершение, взлом, QTE, нокдаун, проходы карт, ману, рассудок, испытания,
возврат к цветку, зависимость, казино, алхимию, воскрешение, чуму, состояния
Призрака, медицину, Шамана, краску, орхидею, рулетку, генератор, ловушки,
статусные эффекты, магазин Агента и набор Урсы.
Аудит — [maniac-3c-mechanics-audit.json](maniac-3c-mechanics-audit.json).

Использованы 14 оригинальных иллюстраций руководства: компьютеры/QTE, нокдаун,
двери/люки/вентиляция, зависимости, алхимия и отдельные системы персонажей.
Они не заменены сгенерированными игровыми скриншотами. Картинки принадлежат
entry конкретной статьи, а не глобальному каталогу иллюстраций.

## Связи и архитектура

Каталоги используют облегчённые `item-catalog.json` / `mechanic-catalog.json`.
Подробные `item-articles` / `mechanic-articles` загружаются собственными entry
через прежний `routePage`; старый SSG предварительно загружает entry для
`renderToString`, клиент — для гидратации. Runtime SSR, CMS и новый роутер не добавлены.

Единый реестр дополнен существующими сущностями. `relatedEntityIds()` выводит
обратные связи из исходных отношений: персонаж ↔ предмет, предмет ↔ способность,
перк ↔ предмет/механика и связи механик. Используется `EntityLink` и только
реально опубликованные URL. Повторы уже показанных связей скрываются.
Главная Wiki и её навигация открывают предметы/механики; карты остаются без ссылки.

Малые общие метаданные и ссылки ресурсов разделяются страницами; не обещается
нулевая загрузка сведений о других сущностях. Проверяются отсутствие чужих
полных статей, крупных изображений, текстов хроник и eager Three/GLB.
Точные запросы, байты и модули каждого маршрута — [MANIAC_3C_BROWSER.json](MANIAC_3C_BROWSER.json).

Холодное открытие в локальном production preview; сумма несжатых JS-body,
без HTML/CSS/изображений (это не gzip-размер):

## Проверки и воспроизведение

Обязательные команды выполнены успешно: `npm run typecheck`, `npm run build`,
`npm run check`, `npm run format:check`, `npm run build:maniac-preview`.
`npm run check` проверяет 185 HTML-маршрутов, ссылки/404, 168 сущностей,
66 регистраций, изображения/provenance, 21 исторический снимок, старые
персонажи/перки/способности, 24 секции хроник и изоляцию чанков.

`npm run check:systems:browser` успешно проверил все 99 новых страниц production preview в Edge:
все новые прямые URL с JS и без него, сохранение DOM при гидратации, собственные
статьи/картинки, поиск, все категории и подтверждённые фильтры персонажей,
пустой результат/сброс, клавиатурный SPA-переход и крюк ↔ способность.
Десять страниц проверены на 320/390/768/1440 px; горизонтального переполнения нет.
Сохраняются 12 полных desktop/mobile-скриншотов и viewport-копии.
Дополнительно браузер открывает настоящий 3D Хранителя по кнопке и сбрасывает
камеру, проверяет фоновые анимации всех трёх хроник и сохранение Google/Yandex URL.
Визуально просмотрены каталог, зажигалка, посох и кошмарное испытание.

Для браузерных команд задайте абсолютный путь `PLAYWRIGHT_MODULE`, если
Playwright установлен во внешнем runtime. Для снимков используется
`WIKI_SCREENSHOT_DIR`; без него — `.audit/wiki-3c-screenshots`.
Скрипт сам поднимает временный production-сервер и закрывает его после проверки.

Подготовка контента из `website` с Python/Pillow:

1. `python scripts/prepare-maniac-systems.py --fetch` — pinned-кэш, аудит и очередь рендеров.
2. `node scripts/render-maniac-systems.mjs` — статичные модели; `--missing` сохраняет существующие PNG.
3. Повторить Python-подготовку и Prettier для выходных TS/JSON, затем npm-проверки.

Зависимости сайта и lockfile не изменены. При обычной сборке сеть/Python/рендерер
не нужны: проверенные выходные данные и изображения находятся в Git.
Известные предупреждения Vite: игнорируемая `use client` React Router,
размер изолированного 3D-чанка и standalone DEV Preview. Новые статьи не грузят
этот движок. Локальная сборка без SITE_URL остаётся noindex без sitemap.
В семи middleware-only SSR-проверках отключён ненужный client dependency scan
(`optimizeDeps.noDiscovery`, пустой include). Это устраняет фоновую гонку
сканирования/закрытия тестового сервера; production-конфигурация не меняется.
Последний `npm run check` завершился без фоновых ошибок сканирования.

Основные изменения находятся в `wiki/data`, `wiki/pages/items`, `wiki/pages/mechanics`,
`SystemsCatalogPage`, `SystemsArticlePage`, `RelatedLinks`, маршрутах/публикации,
`assets/wiki/systems` и скриптах подготовки/проверки. Логотипы, шрифты,
главная NecroDwarf, другие проекты, скачивание и модели маньяков не изменялись.
Карты (3C-2), финальный редизайн, устранение дефектов самого мода и полный
аудит внешнего датапака оставлены за пределами этапа.
