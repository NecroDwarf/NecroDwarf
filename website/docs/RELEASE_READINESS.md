# Итоги исправлений перед выпуском — 1 ноября 2026

## Результат

Семь пунктов согласованного плана исправлений выполнены. Репозиторий проверен
локально на Windows, Node.js 22.13.0 и Chromium из Playwright 1.64.1.
Сборка содержит 190 опубликованных маршрутов и отдельную 404.

Это итог проверки кода и локальной сборки. Настройки аккаунтов, домен, Cloudflare
и старый GitHub Pages не менялись; production-деплой не выполнялся.
Полное соответствие всему продуктовому ТЗ этим отчётом не утверждается.

## Закрытые замечания

1. **Распознавание характеристик.** `stat-text.ts` сохраняет предлог в «с 5 HP»
   и распознаёт «10 с» как время. Регрессионные примеры проверяют смысл символов
   и сохранение исходного текста; проверены готовые каталог и статья «Независимость».
2. **Общие числовые данные.** В текущих каталогах 11 числовых копий заменены
   типизированными `valueRef` на `gameplayFacts`. Одновременные `value`/`valueRef`
   и неизвестная ссылка отклоняются. Проверка меняет факты до загрузки модулей
   только в памяти: текущие таблицы и описание бинтов следуют изменениям,
   исторические снимки остаются прежними. При рефакторинге данные всех 171
   сущностей и отдельный набор исторических снимков совпали с исходным состоянием.
3. **Зависимости ссылок Wiki.** Имена и URL разрешаются через лёгкие метаданные
   публикации. Общие игровые факты отделены от каталога предметов на уровне чанков.
   `check:loading` запрещает полные каталоги, реестр и 3D в зависимостях ссылок
   и страницы эффектов. Числовые характеристики остаются у своих потребителей.
4. **Обратные ссылки эффектов.** `RelatedEffects` подключён к шаблону перков
   и способностей, а также к связанным персонажам. Проверка готового HTML
   подтверждает все 30 объявленных связей в обе стороны. Небольшие компоненты
   ссылок объединены в один модуль; прежние пути импорта сохранены.
5. **Производные сведения в JSX.** Количества в каталогах, фильтрах, на главной
   Wiki и в SEO берутся из данных. Для SEO используются лёгкие метаданные.
   Привязки перков к Reforge находятся в `data/reference-chronicles.ts`;
   названия и адреса хроник в статьях перков/способностей берутся из реестра релизов.
6. **Браузерное окружение.** Playwright зафиксирован в devDependencies и lockfile.
   `browser-check.mjs` управляет браузером, сервером, загрузчиком модулей и ошибками.
   По умолчанию используется Chromium, Edge доступен через `BROWSER_CHANNEL`.
   Результаты сохраняются в игнорируемом `build/browser-checks`, исторические
   отчёты не перезаписываются. Добавлен отдельный job CI с загрузкой артефактов.
7. **Документация и финальная проверка.** Обновлены README обоих уровней,
   инструкции добавления проекта и браузерных проверок. Старые аудиты отмечены
   как исторические. `noUnusedLocals` и `noUnusedParameters` включены в обычный
   typecheck. Добавлена проверка меню, эффектов, фокуса и возврата из статьи.

## Проверки

- `npm run build` — успешно, включая строгий typecheck: 190 страниц и 404.
- `npm run check` — успешно: маршруты, HTML, метаданные, ресурсы, источники,
  исторические снимки, связи, каталоги, эффекты, текст и изоляция чанков.
- `npm run format:check`, отдельная проверка изменённых Markdown и
  `git diff --check` — успешно.
- `npm ci --dry-run --ignore-scripts --no-audit --no-fund` — успешно на шаге 6.
  Это проверка согласованности manifests, не чистая переустановка окружения.
- На шаге 6 прошли все четыре браузерных набора: `check:wiki:browser` — 17
  прямых URL, `check:reference:browser` — 58, `check:systems:browser` — 99,
  `check:maps:browser` — 4; всего 178 прямых URL. Проверены HTML без JS,
  гидратация, изоляция ресурсов, фильтры, клавиатура, SPA/якоря, 3D и reduced motion,
  ширины 320/390/768/1440. Отчёты и скриншоты сохранены в `build/browser-checks`.
- На шаге 7 `npm run check:navigation:browser` подтвердил вложенное мобильное меню,
  закрытие Escape с возвратом фокуса, поиск/пересечение/сброс фильтров эффектов,
  видимость цели якоря, клавиатурный переход и восстановление URL/поиска/прокрутки
  после Back. Эта проверка включена в `check:browser` после четырёх наборов.
- После успешных полных браузерных наборов код приложения не менялся:
  на финальном шаге менялись документация, проверки и настройки компилятора.
  Полные наборы повторно не запускались; результаты шага 6 относятся к тому же
  коду приложения. Заключительный сценарий навигации выполнен отдельно.
- С `SITE_URL=https://example.invalid` выполнены полная локальная сборка и
  `node scripts/check-build.mjs`: canonical/метаданные и sitemap всех 190 URL
  проверены в production-ветке логики. Это зарезервированный тестовый origin,
  не адрес сайта. После проверки восстановлена обычная noindex-сборка без sitemap.
- Отдельно проверено, что принудительное падение browser-callback закрывает
  браузер и освобождает порт, а успешный повтор очищает устаревший failure-отчёт.

Первые браузерные прогоны выявили гонку немедленного чтения количества карточек
и устаревший селектор доступного имени ссылки. Они исправлены в тестах с сохранением
проверок: используется ожидание DOM и точный адрес перехода. Промежуточное превышение
бюджета JS устранено группировкой компонентов; ограничения не ослаблены.
Сохраняются предупреждения сборки об игнорировании `use client` React Router
и размере изолированного 3D-чанка больше 500 kB. Обычные страницы не загружают 3D.

## Границы готовности

- GitHub Actions настроен, но не выполнялся в удалённом GitHub в рамках этой
  работы. Реальный прогон на Ubuntu ещё нужен после push/PR. Локально проверен
  Chromium; отдельный повтор в Edge не проводился.
- Не проверялись настоящий домен, Cloudflare preview/production, HTTPS на домене,
  переходы со старых адресов и актуальная доступность внешних архивов скачивания.
  Эти действия относятся к отдельному этапу публикации.
- Браузерные проверки и скриншоты не заменяют полную визуальную приёмку всех
  страниц и проверку с настоящими вспомогательными технологиями.
- Длинные материалы сейчас реализованы как JSON с React-шаблонами. MDX из ТЗ
  ещё не подключён. Новые материалы Wiki, общий поиск по всей Wiki и детализация
  FriendSheep/NovellMaker остаются отдельными продуктовыми задачами.
- Числа, не связанные с общими фактами, остаются допустимыми значениями `Stat`.
  Одинаковые числа с разным игровым смыслом не объединялись. Повторный импорт
  каталога требует сохранения `valueRef`; регрессионная проверка должна обнаружить
  потерянную связь. Исторический баланс не заменяется текущим.
- Исходное рабочее дерево содержало много незакоммиченных изменений. Оно сохранено;
  изменения этих семи шагов не означают отдельный чистый коммит или готовый PR.
