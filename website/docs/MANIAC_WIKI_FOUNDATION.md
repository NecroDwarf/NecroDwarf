# Maniac Wiki и хроники — фундамент 2B-0

Рабочая ветка `test`. Фундамент создан на этапе 2B-0. На этапе 2B добавлены
полные публичные хроники 1.0–1.2. На этапе 3A опубликованы главная Wiki, каталог
и 15 статей персонажей: [отчёт 3A](MANIAC_3A_VERIFICATION.md).

## Структура

```text
src/app/projects/maniac/
  wiki/data/
    types.ts                 типы сущностей, снимков и изменений
    characters.ts            персонажи
    abilities.ts             способности
    perks.ts                 перки
    items.ts                 предметы
    mechanics.ts             механики
    snapshots.ts             проверенные состояния и commit источника
    provenance.json          пути и SHA-256 проверенных исходников/хроник
    registry.ts              общий индекс и селекторы
    versions.ts              связи выпусков с изменениями сущностей
    assets.ts                локальные UI-ресурсы и связь с ID
    publication.ts           план URL и реестр реально опубликованных статей
    validate.ts              проверки уникальности, типов связей и снимков
  wiki/ui/                   карточки, EntityLink, ReleaseEntityChange
  wiki/model/                конфигурации моделей и ленивый viewer
  assets/models/keeper/      GLB, отчёт конвертации и оригинальные ресурсы
  assets/wiki/               только выбранные иконки/текстуры
  assets/imports.json        происхождение и контрольные суммы ассетов
  dev/                       отдельный прототип
```

Данные остаются TypeScript-модулями. CMS, серверная БД и API не нужны.
Все ресурсы входят в локальную статическую preview-сборку; запросов к GitHub при
просмотре модели или карточек нет.

## ID и отношения

ID имеют вид `character:keeper-of-nightmares`, `perk:forget-me-not` и не зависят
от отображаемого русского имени. Kind и формат ID проверяются. Slug описывает
будущий URL, но сам по себе не делает статью опубликованной.

| Тип | Связи |
| --- | --- |
| Character | abilityIds, itemIds, необязательный model |
| Ability | mechanicIds, необязательные icon/stats |
| Perk | эффекты, mechanicIds, icon/stats |
| Item | usage, abilityIds, mechanicIds, необязательная текстура/иконка |
| Mechanic | описание, необязательные характеристики |
| GameVersion | releaseId существующего выпуска, snapshot, added/changed/removed |

В этапе 3A реестр содержит **76 сущностей**, включая всех 15 персонажей,
11 способностей, 15 перков, 32 предмета и 3 механики. Это данные для персонажей
и хроник, а не публикация полных каталогов всех видов сущностей.
Только Хранитель имеет model; пустые просмотрщики другим персонажам не создаются.

`content.ts` страницы Maniac получает прежние три кратких описания через
`characterSummaries`. Тексты сохранены; отдельного дубликата характеристик для
страницы проекта нет. Остальной редакторский текст презентации остаётся самостоятельным.

## История характеристик

Каждая сущность содержит явные `revisions`. В этом срезе:

- `release:1.0`, `release:1.1`, `release:1.2` — пространства исторических снимков.
- `source:8692f66` — проверенные актуальные исходники, **не утверждение о балансе
  конкретного скачиваемого ZIP**.

Источник зафиксирован на commit
`8692f66dc76582144be85d553d43a41f189b64e7` удалённой main мода. Список snapshots
содержит commit чтения документа; для release это дата/commit источника хроники,
а не предположение, что HEAD был исходниками именно той версии игры.
`provenance.json` фиксирует хеши прочитанных файлов. Локальная копия мода содержит
незакоммиченные изменения и в эту систему не импортировалась.

`getRevision(id, snapshot)` не подставляет актуальные значения, если исторического
снимка нет. Возвращается undefined, а карточка явно сообщает об отсутствии
подтверждения. Селектор без аргумента snapshot использует только verifiedSource.

Пример «Незабудки»:

| Характеристика | Хроника 1.2 | Исходники 8692f66 |
| --- | --- | --- |
| Стоимость возврата | 10 маны | 10 маны |
| Подготовка | 3 с | 3 с |
| Запрет после удара | 10 с | 10 с |
| Перезарядка возврата | В хронике не указана | 60 с |
| Перезарядка при прерывании | В хронике не указана | 30 с |

Отсутствие числа не означает ноль. Перезарядки из кода не появляются в карточке
хроники 1.2. Существующие числа проверены непосредственно в хронике и константах
`ForgetMeNotPerk.java`; значения других перков не угадывались.

Чтобы добавить следующий выпуск:

1. Добавьте его метаданные в прежний `changelogs/registry.ts`, без дублирования.
2. Зарегистрируйте источник снимка в snapshots и его происхождение.
3. Добавьте полный проверенный набор характеристик сущности для нужного снимка.
   Не редактируйте старые числовые массивы под новый баланс.
4. В versions создайте изменение со стабильным ID, before/after и независимым
   editorial. Для added нужен after; removed — before; changed — оба.
5. Полный авторский текст будущего обновления храните отдельно, например в MDX
   внутри changelogs. Не генерируйте его из актуальных описаний Wiki и не сокращайте
   до записей change index. На этом этапе пустые MDX-файлы не создавались.

`coverage: "partial"` обозначает неполный индекс версии. Пустые changes для 1.0
и 1.1 не утверждают, что в выпусках не было изменений. Существующие оригинальные
хроники остаются источником. Теперь полные тексты хранятся отдельно в
changelogs/content, а индекс 1.2 связывает все 15 цветочных перков. Полнота текста
проверяется отдельно от частичного индекса структурированных игровых изменений.

## Компоненты и публикация

CharacterCard, AbilityCard, PerkCard и ItemCard используют общий EntityCard.
Варианты `compact` и `detail` сохраняют один механизм чтения данных: компактный
вариант предназначен для хроник, подробный показывает связи и источники.
ReleaseEntityChange принимает запись изменения и передаёт точные before/after
снимки. Он не подменяет editorial данными Wiki.

EntityLink выводит ссылку только из `publishedEntityRoutes`: сейчас это 15 статей
персонажей. Другие сущности остаются текстом. Проверка требует, чтобы каждый
зарегистрированный адрес действительно был в публичных routes.

Опубликованы на этапе 3A:

- `/projects/maniac/wiki`
- `/projects/maniac/wiki/characters`
- `/projects/maniac/wiki/characters/:slug`

Следующие этапы (пока не опубликованы):
- `/projects/maniac/wiki/perks`
- `/projects/maniac/wiki/perks/:slug`
- `/projects/maniac/wiki/abilities/:slug`
- `/projects/maniac/wiki/items/:slug`
- `/projects/maniac/wiki/mechanics/:slug`

Навигация, локальный поиск по имени и фильтр стороны реализованы в каталоге 3A.

## 3D: исходники, конвертация, runtime

Связка модели подтверждена `KeeperNightmareModel.java`: windigo.geo.json,
windigo.png и windigo.animation.json. Одна модель Хранителя, без переключателя форм.
В runtime передаётся конфигурация CharacterModel с URL GLB, названием и направлением
камеры. ModelCanvas не знает ID Хранителя и может использовать другие GLB.
Если модель изменится, сохраняйте отдельный ID/ресурс для исторических конфигураций.

Выбран **build-time экспорт GLB**, а не попытка открыть GeckoLib JSON GLTFLoader.
Конвертер поддерживает используемый в этом ресурсе Bedrock 1.12: кубы, иерархию
костей, pivot, вращения, inflate, box/per-face UV, отрицательные UV-размеры и
плоские детали. Неподдерживаемые UV-вращения отклоняются явно.

Преобразование координат соответствует импорту Bedrock в Blockbench: отражение X,
отрицательные X/Y вращения, порядок ZYX, единицы 16:1. Особая развёртка UV верхней
и нижней граней обработана отдельно. Геометрия объединяется по кости; glTF Transform
делает dedup/weld/prune. Имена 22 костей и все 84 исходных куба сохранены, включая
18 плоских деталей. Получено 848 треугольников, один материал, GLB около 105 КБ.
Оригинальная PNG-текстура 128×128 встроена без изменения байтов. Используются
nearest-сэмплинг, двусторонний материал и cutout alpha mask. Освещение preview
собственное; точное воспроизведение всех Minecraft shader/render-state эффектов
не заявляется. Draco/KTX2 не добавлялись: для такой небольшой модели декодеры
усложнили бы загрузку без практической необходимости.

Анимации **не воспроизводятся**: GLB содержит статическую bind pose.
В оригинале есть idle, Walk, swim и attack; JSON сохранён для следующего шага.
Не реализованы GeckoLib/Molang/controllers и трансляция ключей в glTF clips.
Это явное ограничение прототипа; меню анимаций с неработающими пунктами не добавлено.

Viewer загружается по кнопке через React.lazy внутри заранее загруженного модуля
статьи Хранителя. Движок и GLTFLoader находятся в отдельном динамическом чанке;
GLB запрашивается только после кнопки. Главная и каталог Wiki их не загружают.
Статичная сцена рендерится
только при загрузке, resize и изменении камеры; нет вечного RAF/автовращения.
Это поведение сохраняется при prefers-reduced-motion. DPR ограничен двумя.
Есть drag/touch, wheel/pinch, доступные кнопки вращения/масштаба/сброса.
Камера вписывает реальные вершины в текущий aspect, включая портретные экраны;
с 2B-0.1 пустые углы мирового bounding box не уменьшают начальный масштаб.
При размонтировании освобождаются controls, observer, RAF, геометрии, материалы,
текстуры/ImageBitmap и WebGL-контекст; поздняя загрузка после unmount тоже очищается.
Без WebGL/при ошибке загрузки остаётся текстовый fallback и описание персонажа.

## Запуск прототипа

Из `website`, Node 22.12+:

```powershell
npm ci
npm run dev:maniac
# http://127.0.0.1:5175/__maniac-lab
```

Проверка готовой preview-статики:

```powershell
npm run build:maniac-preview
npm run preview:maniac
# http://127.0.0.1:4175/maniac-lab.html
```

Это отдельный HTML entry с noindex, отдельным каталогом `.preview/maniac` и
отдельным локальным сервером. `npm run build` теперь собирает 28
публичных маршрутов в build/client. DEV lab остаётся отдельным; публичные страницы
Wiki теперь включены в build/client, но не включают lab.

Ресурс уже готов и находится в Git. После изменения оригинала (и обновления
imports.json/provenance) его можно пересобрать:

```powershell
npm run assets:maniac
npm run typecheck
npm run build
npm run check
npm run format:check
```

Конвертация не обращается к репозиторию мода или сети: все три исходника сохранены
локально. `.prettierignore` защищает точные байты upstream JSON/PNG от переписывания.
Источник перед копированием нужно отдельно проверить и зафиксировать commit/hash.

## Оформление иконок — этап 2B-0.1

Замечания команды к техническому preview от 25.10.2026 реализованы в общем
EntityIcon. Текущий preview остаётся изолированным прототипом.

- Иконки должны вписываться в карточки: использовать согласованное обрамление,
  подложку или мягкий переход к фону, чтобы изображение не выглядело случайно
  вставленным квадратом. Сохранять узнаваемость оригинала и чёткость пиксельных деталей.
- Для «Кошмарной зажигалки» не показывать развёртку текстуры как готовую иконку.
  Подготовить статичный рендер оригинальной 3D-модели предмета с его текстурой;
  отдельно проверить соответствие игровому виду. Интерактивный WebGL для иконки
  не требуется.
- Размер подбирать по видимой области рисунка, а не только по размеру файла.
  Для «Концентрированного кошмара» учитывать пустые поля,
  кадрировать или масштабировать представление без потери важных деталей.
  Проверить читаемость в compact/detail карточках на desktop и mobile.

Готовая реализация, метаданные, команды подготовки и скриншоты:

## Загрузка будущих публичных статей

Для этапа публичной Wiki использовать общий `src/app/shared/lib/route-page.ts`:
каждый опубликованный маршрут подключает собственный модуль статьи через
`routePage(() => import(...).then(m => m.default))`. Сам модуль импортирует только
свой текст/MDX и нужные данные. Каталог и реестры ссылок содержат метаданные, без
статических импортов всех статей. Не дополнять общий `wiki/data/registry.ts`
полными текстами статей: сейчас это небольшая база игровых карточек, которую
потребляют Maniac и хроники, а не контейнер будущей энциклопедии.

Загрузчик одинаков для build-time SSG, начальной гидратации и SPA-переходов;
добавлять `React.lazy` поверх него не требуется. Проверять полный HTML без JS и
границы зависимостей новых статей в `check-route-loading.mjs`.
Подробный контракт и замеры: [ROUTE_LOADING.md](ROUTE_LOADING.md).
Этот контракт применён в 17 публичных Wiki-маршрутах этапа 3A. DEV Preview остаётся отдельным.
