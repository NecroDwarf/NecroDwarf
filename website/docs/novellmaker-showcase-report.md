## Документация и производительность

Оригиналы Markdown хранятся локально. Компилятор на базе Marked создаёт безопасное
дерево React-элементов; произвольный HTML показывается текстом, разрешены только
явные якоря. Нет `dangerouslySetInnerHTML`, Lua VM и исполнения кода из документации.
Таблицы и блоки кода прокручиваются внутри собственных областей.
Highlight.js работает только при генерации: Lua, JSON, PowerShell и C#.
Обе новые зависимости относятся к devDependencies.

Все 21 документа имеют отдельные route chunks с единственным собственным JSON.
Ни Markdown-парсер, ни Highlight.js, ни Three.js, ни данные Maniac Wiki не входят
в зависимости страниц NovellMaker. Полные навигационные метаданные и загрузчики
статей загружаются при открытии справочника; заголовки SEO разрешаются во время
обязательного `routePage.preload()` до SSG, гидратации и обновления head.

Поиск содержит 218 записей: документы, заголовки и все функции. Индекс загружается
только после нажатия кнопки поиска. Точное совпадение имени функции имеет высший
приоритет; сравнение не зависит от регистра, русский и английский поддерживаются.

Сохранены прежние ограничения роста общего JavaScript в тесте карт Maniac:
менее 3% к зафиксированному baseline. Бюджеты и существующие проверки не ослаблены.
Старые тесты адаптированы к новому объёму и содержимому: отдельные точные проверки
191 прежнего и 22 новых маршрутов вместо прежнего общего количества 191;
в SPA-переходе из FriendSheep проверяется точный новый заголовок NovellMaker.
Проверки изоляции темы, навигации и бюджетов сохранены.

Производственная сборка использует только локальные файлы. Обычный build
перегенерирует представление документации, но не обращается в GitHub и не
обновляет исходный commit. Без `SITE_URL` существующая сборка оставляет noindex
и не выпускает sitemap; при заданном origin новые маршруты входят в общий sitemap.

Vite сообщает о директиве `use client` внутри React Router и крупном существующем
chunk `ModelCanvas` (около 644 КБ). Это неблокирующие предупреждения; 3D-код
изолирован и не загружается страницами NovellMaker.

## Обновление источников

Требуются Git и Python 3. В отдельной чистой локальной копии движка откройте
закреплённый commit. Из `website/` выполните:

```powershell
# Если python не находится в PATH, задайте полный путь к установленному Python:
$env:PYTHON = 'C:/path/to/python.exe'
npm run docs:novellmaker:sync -- C:/path/to/NovellMaker
npm run docs:novellmaker
npm run build
npm run check
npm run format:check
npm run check:browser
```

Синхронизация проверяет commit и чистоту копии, запускает оригинальную Python-проверку,
сохраняет реестр API, дерево путей, хеши оригиналов и изображения примеров.
Markdown читается из Git blob, поэтому результат не зависит от CRLF/LF рабочей копии.
Точечный атрибут `-text` сохраняет записанные байты в репозитории сайта.
Смена commit выполняется явно в `scripts/novellmaker-reference.mjs`; при переходе
на другую ревизию также обновляются ссылки примеров в `content.ts` и блок
происхождения в `docs/ui/DocsLayout.tsx`. Затем нужно повторить исследование
контрактов, синхронизацию и полный набор проверок.

Оба запрошенных этапа входят в эту реализацию. На будущее остаются материалы
для реального публичного релиза и настоящие скриншоты после запуска подходящей
версии редактора; до появления такого релиза скачивание не предлагается.
