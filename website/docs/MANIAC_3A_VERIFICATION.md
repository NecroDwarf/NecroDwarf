# Этап 3A — публичная Maniac Wiki: персонажи

Дополнение от 28.10.2026: [звёзды сложности, значки характеристик и изображения
снаряжения](MANIAC_ICON_SYSTEM.md). Приведённые ниже сетевые замеры фиксируют
исходный результат 3A до добавления этой визуальной системы.

26 октября 2026. Ветка `test`. Реализовано в коде сайта; production-деплой и
слияние в `main` не выполнялись. Исходный репозиторий игры не изменялся.

## Результат

Добавлены 17 публичных SSG-маршрутов:

- `/projects/maniac/wiki` — главная энциклопедии с категориями, Хранителем и хрониками.
- `/projects/maniac/wiki/characters` — весь каталог, поиск по имени и фильтр стороны.
- `/projects/maniac/wiki/characters/:slug` — 15 полноценных статей.

Всего у сайта 28 маршрутов и отдельный 404. Wiki доступна из страницы Maniac.
Из статей доступны каталог, Wiki, Maniac, хроники и NecroDwarf. Перки, предметы,
способности, механики и карты пока не получают пустых публичных URL.

Horror Tech × Game Encyclopedia: большие оригинальные фрески, тёмные поверхности,
приглушённые красные акценты маньяков и холодные акценты выживших. Geologica/Rubik
и бренд сайта сохранены. Фрески в карточках и статьях показаны целиком через
`object-fit: contain`; никаких генерированных игровых изображений.

## Источники и различия версий

Проверены 64 текстовых/конфигурационных источника в `wiki/data/provenance.json`,
включая основные классы, локализацию, реализации предметов, `ModItems`,
`NightmareConfig` и прежние материалы. Новые файлы сверены с Git blob SHA
закреплённого дерева; сохранены SHA-256 и размеры оригинальных байтов.

- Исторические `release:1.0–1.2` не перезаписаны. Прежние три редакторских
  описания персонажей на странице Maniac сохранены, дополнены только связи Wiki.
- `source:8692f66` — проверенный снимок исходников, **не подтверждение баланса
  скачиваемого ZIP 1.2**. Разница явно обозначена на страницах Wiki.
- Описания берутся из действующей русской локализации. Числа из старых
  Java-fallback строк не добавляются, когда локализация их не показывает, а
  реализация отдельно не проверена. Ранее подтверждённые характеристики
  «Концентрированного кошмара» сохранены в карточке.
- `addFeature` не превращён автоматически в способность. Отдельные действия
  добавлены после проверки связанных классов предметов/обработчиков: телепорт
  Смерти, прыжок Урсы, чумной сгусток, одержимость/невидимость Призрака,
  музыкальная волна, перенос урона Доктора, квантовая телепортация и облако дыма.
  Пассивные особенности и расходуемые предметы остаются в своих разделах.
- `CharacterLoadoutPreview` прямо обозначен в исходниках как presentation-only.
  Поэтому статьи называют раздел «Снаряжение», не объявляя каждую запись
  гарантированным стартовым инвентарём. Игла пробуждения подписана как предмет
  выживших для кокона, а не оружие Хранителя.

Для команды остаётся согласовать соответствие этого source-снимка выпущенному
архиву 1.2 и при необходимости проверить фактическую выдачу вещей логикой
матча/датапаком. Отдельно известны расхождения числовых fallback-описаний с
реализациями (например, число первых лабиринтов и параметры зависимости).
В статьи не переносились спорные числа. Minecraft-матч в этой задаче не запускался.

## Фрески и иконки

Все 15 PNG из `textures/gui/frescos/{gameId}.png` сопоставлены по настоящему ID.
Оригиналы суммарно занимают 19 198 767 байт. Подготовлены 30 WebP: максимальная
сторона 480 для каталога и 1100 для статей, без увеличения небольших оригиналов.
Композиция не обрезается, исходная прозрачность сохраняется; при подготовке
проверяется равенство alpha-канала до и после WebP. Размеры/хеши производных
файлов и оригинальные Git/SHA-256 — `assets/characters/imports.json`.
Оба набора WebP суммарно занимают **4 048 180 байт** вместо 19 198 767 байт
одного набора оригинальных PNG; уменьшение примерно на 79% при сохранении alpha.
Ресурсы локальные, запросов к GitHub при чтении нет. Вне hero — lazy loading.

Дополнительно подготовлены восемь оригинальных GUI-иконок активных действий;
они используют `EntityIcon` и существующие подложки/рамки. Развёртки текстур
3D-предметов не подставляются вместо готовой картинки. Кошмарная зажигалка
использует прежний рендер открытой оригинальной модели. Для остальных предметов
без готовой подходящей иконки оставлена содержательная текстовая карточка.

## Данные и загрузка

`wiki/data/characters.ts` остаётся единым реестром. `character-catalog.json` —
облегчённая проекция проверенных классов; `character-articles/*.json` содержит
только полные особенности соответствующей статьи. Предметы и способности
проецируются в существующие типы сущностей. Общий каталог не импортирует полные
статьи. Служебный `route-metadata.ts` генерируется из тех же сведений; тест
проверяет совпадение ID/slug/имени, чтобы не возник второй ручной реестр.

Каждая статья имеет отдельный entry в `wiki/pages/characters/` и подключена
существующим `routePage`. Перед SSG/гидратацией разрешается только модуль текущего
маршрута. Полный HTML остаётся доступным без JS; каталог без JS показывает все
15 персонажей. Клиентский поиск не требует API или библиотеки.

Статические зависимости страницы не включают JSON других статей, большие фрески
других персонажей, тексты хроник или Three.js. Небольшая база карточек и общие
UI-модули переиспользуются. `publishedEntityRoutes` содержит только 15 реально
опубликованных статей; существующие связи хроник теперь открывают эти страницы.
Ссылки из статей ведут в конкретные подтверждённые разделы хроник:
появление трёх персонажей в 1.1, изменения Смерти в 1.2, изменения связанного
снаряжения/механик в Reforge. Даты появления не выдумывались.

Хранитель — единственный персонаж с моделью. Его entry подключает конфигурацию
и viewer, а `ModelCanvas`/Three.js и GLB загружаются только после кнопки.
Поддержаны drag/touch, zoom, кнопки поворота/сброса и WebGL fallback.
Анимации и дополнительные формы не имитируются. DEV Preview остаётся отдельным.

Точные холодные запросы всех 17 URL и размеры JS:
[MANIAC_3A_BROWSER.json](MANIAC_3A_BROWSER.json).
Gzip/CDN-время не измерялись; байты — тела несжатых JS-ответов локального preview.

статей. Основной объём начального JS — общий React/React DOM/Router.

## Проверки и воспроизведение

```powershell
cd website
npm run typecheck
npm run build
npm run check
npm run format:check
npm run build:maniac-preview
$env:PLAYWRIGHT_MODULE = 'C:/path/to/playwright/index.mjs'
$env:WIKI_SCREENSHOT_DIR = 'C:/path/to/screenshots'
npm run check:wiki:browser
```

Playwright/Edge используются только для локального QA и не добавлены в
зависимости сайта. `check-maniac-characters.mjs` встроен в общий `check`;
`check-route-loading.mjs` расширен на каждый Wiki entry и отсутствие eager 3D.
Существующие проверки полноты 24 разделов хроник, снимков и скачивания сохранены.

Итог: все пять обязательных команд и `check:wiki:browser` завершились успешно.
Ошибок гидратации, JS, отсутствующих ссылок и горизонтальной прокрутки не выявлено.
Известные предупреждения сборки: React Router `use client` и размер отдельного
ленивого Three.js-чанка. Оба не препятствуют сборке; 3D не попадает в холодную загрузку.

Браузерный аудит проверяет каждый прямой URL с JS и без него, сохранение DOM
при гидратации, отсутствие ошибок консоли, реальные запросы, поиск (включая ё/е),
пересечение фильтров, пустой результат/сброс, клавиатурный SPA-переход, отсутствие
переполнения на всех 17 страницах при **320/390/768/1440 px**, reduced motion,
загрузку и управление моделью и fallback при отключённом WebGL.

Сняты главная Wiki, каталог, Хранитель, Призрак и Доктор на desktop/mobile,
отдельно кадр с загруженной моделью. Абсолютные пути артефактов сохранены в
JSON-отчёте; в том же каталоге лежат `*-viewport.png` для первого экрана.

Повторная подготовка источников (Python + Pillow, исходники из закреплённого
commit должны лежать в локальном audit-кеше):

```powershell
python scripts/prepare-maniac-characters.py --source-root ../.audit/maniac-source-8692f66 --fetch
npx prettier --write src/app/projects/maniac/wiki src/app/projects/maniac/assets/characters/imports.json src/app/projects/maniac/assets/imports.json
npm run build
npm run check
```

`--fetch` скачивает только исходники/оригинальные изображения в audit-кеш и
проверяет Git-хеши; никаких runtime-сетевых зависимостей. Скрипт намеренно
закреплён на конкретном commit и явных проверенных отношениях способностей.
Переход на другой снимок требует повторного аудита, а не замены строки SHA.

## Изменённые области и следующие этапы

- `wiki/pages/`, `wiki/routes.ts`, `wiki/route-metadata.ts` — новые страницы,
  оформление, фильтры и отдельные входы статей.
- `wiki/data/`, `wiki/ui/EntityCards.tsx` — дополнение существующего реестра,
  источники, опубликованные ссылки и отложенные технические подробности карточек.
- `assets/characters/`, `assets/wiki/abilities/`, `assets/imports.json` — настоящие
  изображения, размеры и контрольные суммы.
- `src/app/routes.ts`, `ManiacPage.tsx` — регистрация готовых URL и вход в Wiki.
- `scripts/prepare-maniac-characters.py`, `check-maniac-characters.mjs`,
  `check-maniac-wiki-browser.mjs`, существующие check-скрипты и `package.json`
  — подготовка и проверки.
- README, PROJECT_CONTENT, CONTENT_SOURCES и документация Wiki — инструкции.

Полные каталоги перков/предметов/способностей/механик/карт, новые модели и
анимации остаются следующим этапам. Главная NecroDwarf, логотипы, шрифты,
скачивание 1.2 и тексты хроник не перерабатывались.
