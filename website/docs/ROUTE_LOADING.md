# Загрузка маршрутов перед публичной Maniac Wiki

Проверено 26 октября 2026, ветка `test`. Без новых зависимостей, runtime SSR,
смены роутера, деплоя и слияния в `main`.

## Что показал исходный аудит

Production Vite собирал один `assets/index-AqR440PG.js`: **428 074 байта**,
gzip 123 431 байт. Его статический граф включал все страницы, `ChroniclePage`,
все три JSON хроник и базу игровых карточек. Холодные запросы к главной,
Maniac, любой хронике и обоим спискам загружали этот же файл. Поэтому рефакторинг
устраняет подтверждённую загрузку, а не только предполагаемую проблему.

Исходный граф и фактические JS-ответы: [loading-before.json](loading-before.json).
Новый граф и ответы: [loading-after.json](loading-after.json).

## Методика и результат

Одинаковая production-сборка `npm run build`, локальный `createStaticServer`
из `scripts/serve.mjs`, headless Microsoft Edge через Playwright. Для каждого
URL создавался новый browser context без кеша и service workers. После
`networkidle` учитывались тела всех ответов `.js`, включая Vite modulepreload,
затем их модули сопоставлялись с графом Rollup.

**КБ = 1000 байт.** Это сумма JS, а не размер HTML/CSS/изображений. Preview
отдаёт несжатые ответы: gzip ниже — локальная оценка `gzipSync`, а не измеренный
сетевой transfer size Cloudflare. HTTP-заголовки не включены. Время загрузки
и CDN-компрессия не измерялись.

## Что загружается по требованию

## Совместимость с SSG и гидратацией

1. `routePage` кеширует Promise и разрешённый компонент. `read()` синхронный:
   вызов до `preload()` явно считается ошибкой контракта.
2. `entry-server.render()` ожидает нужный модуль **до** `renderToString` внутри
   прежнего `StaticRouter`. Генератор ожидает `render()`. На выходе полный текст,
   карточки, метаданные и прямые HTML-маршруты, без Suspense fallback.
3. `main.tsx` ожидает тот же модуль до `hydrateRoot`. Готовая SSG-разметка всё
   время остаётся в DOM. При сбое начального импорта доступен статический текст.
4. SPA продолжает использовать `BrowserRouter`/`Routes`/`Link`. Пока новый чанк
   загружается, остаётся предыдущая страница в её route context. После загрузки
   обновляются страница, SEO и фокус. Отменённый переход не заменяет новый;
   при ошибке остаётся текст и появляется ссылка повторной загрузки.
5. CSS намеренно общий (`cssCodeSplit: false`), включён обычным `<link>` в каждый
   HTML. Это сохраняет оформление без JS и исключает появление неоформленного
   текста при начальной загрузке. Загрузка CSS по маршрутам — отдельная возможная
   оптимизация, требующая соответствующих SSG stylesheet/preload-ссылок.

## Контракт для будущей Wiki

Добавлять отдельный модуль на статью и явный загрузчик в опубликованный реестр:

```tsx
// Пример будущего маршрута, сейчас он не опубликован.
page: routePage(() =>
  import("./wiki/articles/forget-me-not.page").then((m) => m.default),
)
```

Модуль статьи импортирует собственный MDX/данные; общий каталог содержит только
метаданные/ссылки. Не делать barrel, статически импортирующий все статьи, и не
складывать их тексты в текущий реестр игровых характеристик. Тот же `preload`
используется SSG и браузером, поэтому десятки статей не требуют нового роутера
или runtime-сервера. Дополнять `check-route-loading.mjs` проверками их границ.
Публичная Wiki остаётся следующим этапом, её DEV Preview изолирован.

## Повторение проверок

```powershell
npm run typecheck
npm run build
npm run check
npm run format:check
npm run build:maniac-preview
# Если Playwright установлен вне website/node_modules:
$env:PLAYWRIGHT_MODULE = 'C:/path/to/playwright/index.mjs'
npm run measure:loading -- after
```

Браузерный замер требует установленного Microsoft Edge и локального Playwright;
Playwright не добавлен в зависимости сайта. `before` применяется к исходной
сборке до изменений, сохранённый отчёт не нужно перезаписывать новой сборкой.

Vite manifest записывается в `build/client/.vite/manifest.json`, более подробный
граф исходных модулей — в игнорируемый `.ssg/client-modules.json`.
`check:loading` встроен в `npm run check`: он проверяет статические зависимости
начального чанка, списков и каждой хроники. Браузерный скрипт дополнительно
проверяет реальные ответы, отсутствие ошибок гидратации и пустого состояния,
сохранение DOM-узла заголовка, равенство основного текста с/без JS, CSS без JS,
SPA-переходы с задержкой сети и отменой, mobile/reduced motion, отказ чанка
и неизменность ссылок скачивания. Архив сборки при проверке ссылок не скачивается.

Проверки полноты всех 24 исходных разделов, исторических снимков и игровых
карточек остались в существующих `check`-скриптах. Сборка DEV Preview проверена
отдельно. Известное предупреждение React Router `use client` сохраняется;
в отдельном DEV Preview есть предупреждение о размере ленивого Three.js-чанка.

Итог: `typecheck`, `build`, `check` (включая `check:loading`), `format:check`,
`build:maniac-preview` и браузерный замер завершились успешно. Дополнительно
открыт production DEV Preview: карточки отображаются, `ModelCanvas` и GLB
не запрашиваются до нажатия кнопки, модель загружается после нажатия,
просмотрщик выгружается без ошибок JS. Ссылки скачивания проверены по адресам
и атрибутам, повторная загрузка 220-МБ архива в эту задачу не входила.
